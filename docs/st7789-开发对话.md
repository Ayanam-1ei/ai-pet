## 推荐路径

### 1. 在网页里导出

| 格式 | 用途 |
|------|------|
| **C 数组**（`.h`） | Arduino / PlatformIO，最常用 |
| **BIN**（`.bin`） | ESP-IDF / MicroPython / SPIFFS 文件 |
| **PNG** | 只做预览，不能直接上屏 |

对 240×240 RGB565，一张完整图约 **112.5 KB**。

### 2. Arduino + TFT_eSPI（ESP32 常见）

导出 `img_240x240.h` 放到 sketch 同目录：

```cpp
#include <TFT_eSPI.h>
#include "img_240x240.h"

TFT_eSPI tft = TFT_eSPI();

void setup() {
  tft.init();
  tft.setRotation(0);          // 按实际接线调整 0-3
  tft.fillScreen(TFT_BLACK);
  tft.pushImage(0, 0, 240, 240, img_240x240);
}

void loop() {}
```

`User_Setup.h` 里要配好你的引脚（常见 ESP32 + 1.54"）：

```c
#define ST7789_DRIVER
#define TFT_WIDTH  240
#define TFT_HEIGHT 240
#define TFT_MOSI 23
#define TFT_SCLK 18
#define TFT_CS   15
#define TFT_DC    2
#define TFT_RST   4
// 若有背光：#define TFT_BL 32
```

### 3. Adafruit_ST7789

```cpp
#include <Adafruit_ST7789.h>
#include "img_240x240.h"

Adafruit_ST7789 tft = Adafruit_ST7789(TFT_CS, TFT_DC, TFT_RST);

void setup() {
  tft.init(240, 240);
  tft.drawRGBBitmap(0, 0, (uint16_t *)img_240x240, 240, 240);
}
```

注意：Adafruit 的 `drawRGBBitmap` 要求数组是 **RAM** 或用其 `PROGMEM` 变体；大图建议放 `PROGMEM` 并用支持 flash 读的接口。

## 注意点

1. **字节序**：导出的 C 数组是小端 `uint16_t`，TFT_eSPI / Adafruit 一般直接可用。
2. **全屏塞进 RAM**：240×240×2 = 115200 字节，ESP32 可以放 flash（`PROGMEM`），别全放栈里。
3. **竖屏/横屏**：`setRotation` 改了之后，若要 1:1 不裁切，导出时宽高也要跟着换（例如 240×240 旋转后仍是正方形；135×240 旋转会变 240×135）。
4. **背光**：部分模块 `TFT_BL` 需要拉高才有画面。

## 真正的结论

**BIN 文件是对的，静态刷图通路把颜色极性弄反了。**

| 层 | 状态 |
|----|------|
| 网页裁剪 / RGB565 导出 | 正确（四角 238,242,238 近白） |
| 串口 `frame` 收 115200 字节 | 正确 |
| 上屏 `writeColor` 通路 | **极性反了** → 需 `^ 0xFFFF` |

表情机用 `fillScreen`/`drawPixel` 一直正常，只有 **BIN → writeColor** 这条静态刷图路径极性相反。已在固件里写成常量 `PHOTO_INVERT_MASK`。

## 我一开始判断偏了

1. **只拿「四色块」当验收**
   红绿蓝黄能看见 ≠ 极性正确。反相后红会变青，但「有四个色块」很容易被当成通过。应该当时就检查 **白角/黑角**。

2. **文件分析说对了，却推错结论**
   BIN 平均色近白、四角近白 → 应立刻怀疑「屏上应该大面积亮」。你照片里大面积偏暗，就该直接对比文件 vs 屏幕，而不是先怀疑原图没颜色。

3. **路径换得慢**
   `drawRGBBitmap`（太慢/易 WDT）→ `writePixels`（endian 混乱）→ `writeColor`，每一步都该用同一张 **白/黑/红三色测试图** 验收，而不是只看推送是否 `ok frame`。

## 还留在代码里的债

- `PHOTO_INVERT_MASK` 是 **实测补偿**，不是「标准 RGB565」；换屏/换库要再测

## 用法

```powershell
cd "S:\可视化\clawd mochi"

# 存到槽 1，并作为开机图
python tools\push-frame.py 图A.png --slot 1

# 再存一张到槽 2
python tools\push-frame.py 图B.bin --slot 2

# 切换显示 / 换开机图
python tools\push-frame.py --show 2
python tools\push-frame.py --next
python tools\push-frame.py --prev

# 查看 / 删除
python tools\push-frame.py --list
python tools\push-frame.py --clear 1
python tools\push-frame.py --clear all
```

不带 `--slot` 时仍写入当前槽（默认上次用的那个）。

## 说明

- 每张约 112KB，5 张约 560KB，SPIFFS 1MB 够用
- `--show N` 会记成 **开机槽**，拔电重插就显示这张
- 旧的单文件 `/photo.bin` 会自动迁到槽 0

刚才已把现有图写入 **槽 0**（`ok slots 0`）。你再导出别的 BIN，用 `--slot 1` 存第二张，然后 `--next` 就能切换。
